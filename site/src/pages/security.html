Security and privacy

What leaves the machine, and what never does.

A cheque file holds names, account numbers and a client’s own words. The design keeps as much as possible local and puts a privacy step between the client’s account and any model.

1Papers stay local

Uploads are kept in the desk’s own folder on the advocate’s machine.

2Reading

Page images go to Azure Content Understanding to be read into fields.

3Voice

A recording goes to Azure Speech for text. The recording itself is kept only locally.

4Privacy pass

Azure AI Language finds names, numbers and addresses and masks them.

5Drafting

Only masked text and traced facts reach the drafting model. Nothing is sent onward.

Identity

The desk signs in to Azure with your own Microsoft Entra ID through the standard credential chain. There is no API key in the code, in the repository or in a settings file. If you are not signed in, the desk cannot call Azure, and says so.

The agent’s short lead

The question-answering assistant has exactly two tools: one that reads a matter’s facts and one that reads its counted dates. Both are read-only and scoped to the matter being asked about. It has no tool to write, send, search the web or open another matter.

Approval and audit

Approving a brief records who approved, when, and which version of the facts they approved. That entry cannot be edited from the desk.

Where data goes

  • Papers and recordings: stay on the machine, except the single call that reads them.
  • Client’s account: masked first, then used for drafting.
  • Services run in the Azure region the account is set to. Region changes are made by the account owner.
  • No analytics, no advertising, no tracking of any kind.

This website

It sets no cookies, loads no third-party scripts or fonts, and keeps nothing about you. The sample matters here are fictional and the demo accepts no uploads.

Honest limits

This is a prototype and has not had an independent security review. Do not put a real client’s papers into it.
