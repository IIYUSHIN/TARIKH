How it is built

The pipeline, the services, and what is done.

For a developer, an examiner, or an advocate who wants to know what is under the desk. Everything here is in the public repository.

IntakeUpload

Photo or scan of each paper. Kept locally.

ReadExtract

Content Understanding returns fields with a place on the page.

CountRule engine

Pure code, no model. Four windows, each with its rule.

DraftBrief

Foundry model drafts from traced facts. Unsupported lines are dropped.

GateApprove

A named advocate approves. The approval is audited.

Stack

Small on purpose.

Service

Python with FastAPI, SQLite for matters and the audit log, and a plain static front end. No front-end framework.

Azure

Content Understanding, AI Language (PII detection), Speech, a Foundry model deployment and the Foundry Agent Service. Sign-in through Microsoft Entra ID.

Recording and replay

Every Azure reply can be saved and replayed, so the whole app runs offline and tests never call Azure.

Date engine

Written twice, in Python for the service and in JavaScript for this site, and tested on both sides against the same worked examples.

This website

Static pages generated from templates by one script. One stylesheet, one script, self-hosted fonts, no third-party requests.

Decisions

Each design and legal choice is a short numbered note in docs/decisions, with the alternatives that were rejected.

Run it

On Windows, in PowerShell.

Needs Python 3.11 or newer. The Azure steps are in docs/azure-setup.md; the first command checks each service and says how to fix any that fails.

git clone {{ GITHUB }}.git
cd TARIKH
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
az login
python -m tools.check_setup
python -m uvicorn app.main:build_app --factory --port 8000

To rebuild and test this website:

cd site
pip install jinja2
python build.py
node --test tests/engine.test.js
