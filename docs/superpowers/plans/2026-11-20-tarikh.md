# Tarikh Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Tarikh, a local web app that turns a bounced-cheque matter's papers and a client's voice note into source-linked facts, a cited brief and tested statutory deadlines, plus the 20–30 page CU report and a viva sheet.

**Architecture:** FastAPI + SQLite backend; a deterministic pipeline calls Azure services through small interfaces (Content Understanding, Speech, Language, Foundry model, Foundry agent). A record/replay wrapper stores real runs. Hand-written static front end, no build step.

**Tech Stack:** Python 3.12, FastAPI, pydantic v2, SQLite, pytest, azure-identity, azure-ai-projects, Content Understanding / Speech / Language clients (exact packages confirmed in Task 4), Playwright (tests and screenshots only), python-docx (report).

**Spec:** `docs/superpowers/specs/2026-11-20-tarikh-design.md`

## Global Constraints

- Python ≥3.10 (the Foundry SDK's floor; built on 3.13, must also run on the candidate's laptop version); Azure auth is Entra ID via `DefaultAzureCredential` / `az login`; no keys in files.
- A model never computes a statutory date; deadlines come only from `app/deadlines.py`.
- The UI shows the earlier (safer) date and the rule used; court-holiday and delay-condonation shown as "lawyer to confirm".
- Rule: notice ≤30 days from receipt of bank memo; 15 days to pay, counted from the day after receipt of notice; complaint within one month from the day after the 15 days end.
- PII is redacted before any text reaches the model.
- Replay mode always shows the banner "Replay of recorded run, <timestamp>".
- All sample documents fictional and labelled; no real client data.
- UI copy: plain law-office language. Banned: sparkle/"magic"/"AI-powered" copy, emoji icons, gradient hero, glass cards, stock illustration, Inter/Space Grotesk, three-icon feature grid, lorem ipsum.
- Fonts self-hosted; libraries vendored; no CDN at run time.
- Report: CU format, Times New Roman 12, 1.5 spacing, A4, footer = name / UID / specialization, roman numerals for front matter, main text 20–30 pages.

## Review Focus

1. Receipt date missing or unreadable → window shows "date needed", never a guessed date. (Task 2, Task 5)
2. Month-end arithmetic (period starting 31 Jan, leap years) → period ends on last day of the shorter month. (Task 2)
3. Silent, empty or unsupported-language voice note → clear message; no brief invented from nothing. (Task 6, Task 9)
4. Phone photos (HEIC, huge, rotated) and wrong file types → rejected with a reason or normalised. (Task 9)
5. Azure error, timeout or 429 → readable message, partial results kept, retry possible. (Task 4, Task 9)
6. Model claim without a valid source fact id → dropped and listed under "flagged". (Task 7)

### Task 2: Deadline engine

**Files:** Create `app/deadlines.py`, `tests/test_deadlines.py`.

**Interfaces:**
- Produces: `Window(key, label, opens: date|None, closes: date|None, status, rule, days_left: int|None)` with status in `unknown|upcoming|open|closing|expired|met`; `month_period_end(start: date, months: int) -> date`; `compute_windows(cheque_date, memo_received_on, notice_sent_on, notice_delivered_on, today) -> list[Window]` (all args `date|None`; order: validity, notice, payment, complaint). "closing" = ≤5 days left.

- [ ] Tests (table-driven): `month_period_end(date(2026,4,8),1)==date(2026,5,7)`; `month_period_end(date(2026,1,31),1)==date(2026,2,28)`; `month_period_end(date(2024,1,31),1)==date(2024,2,29)`; `month_period_end(date(2026,1,10),3)==date(2026,4,9)`.
- [ ] Worked examples from published sources: notice delivered 5 May 2017 → payment window 6–20 May 2017; delivered 23 Mar → payment closes 7 Apr, complaint opens 8 Apr, filing on 2 May is inside the window. Missing `notice_delivered_on` → payment and complaint `status=="unknown"`, `closes is None` (Review Focus 1). `today` after `closes` → `expired`; `notice_sent_on <= closes` → notice window `met`.
- [ ] Run: FAIL. Implement; window `rule` strings state the convention and "lawyer to confirm" flags. Run: PASS. Commit.
